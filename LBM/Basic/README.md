# 再分析资料制作 LBM T42L20 背景态

[English](README_EN.md)

**作者：RH_Deng；Codex（OpenAI，AI辅助整理与重构）**  
整理日期：2026-10-25

本工具将全球气压层再分析月资料制作成 **LBM T42L20 干模式使用的三维背景态**。修改 JSON 配置、提供再分析资料和三份模型参考文件，即可运行；不依赖原服务器的账户、目录结构或作业调度系统。

本工具由经过核对的 HPC 背景态制作程序重构，参考了原 DJF 入口及多个季节的扩展程序。原始入口和源代码 SHA256 见 [来源说明](docs/SOURCE_PROVENANCE.md)。输出包含完整的 U、V、T、PS、Q；V 保留资料中的非零结构，未强制设为零。Q 用于虚温地形订正和背景文件兼容，不能据此把本流程理解为已配置好的湿模式。

本包目前固定 **128 × 64 Gaussian 网格、T42 标量谱投影、20 个 σ 层**。输入适配可处理符合下述契约的 MERRA-2、ERA5 或其他再分析 NetCDF；更换产品时需要确认变量、单位、气压层和科学适用性。随包只给出 MERRA-2 的真实资料配置示例，不声称已经用所有再分析产品完成科学验收。

## 1. 环境

从仓库根目录进入本工具目录：

```bash
cd LBM/Basic
```

需要 Python 3.11 或更新版本，以及 `numpy`、`scipy`、`netCDF4`。绘图为可选功能，另需 `matplotlib`。可在自己的 Python 环境中安装：

```bash
python -m pip install -r requirements.txt
```

在代码根目录直接运行 `python -m lbm_background` 即可。也可安装为可编辑包；需要绘图时选择 `plots` 扩展：

```bash
python -m pip install -e .
python -m pip install -e ".[plots]"
```

这里的 `python` 应替换为自己的解释器；本地执行仍应遵守个人环境中指定解释器的约定。程序不调用 LBM 模型可执行文件、Fortran 编译器、NCL 或 CDO，也不提交调度作业。

## 2. 需要准备的文件

### 再分析资料

必需字段及内部标准如下。JSON 中的字段名固定，源 NetCDF 的变量名由 `variable` 配置。

| 字段键 | 含义 | 支持的输入单位 | 内部单位 |
| --- | --- | --- | --- |
| `U`、`V` | 纬向风、经向风 | m s⁻¹ 的常用 CF 写法 | m s⁻¹ |
| `T` | 气压层气温 | K 或摄氏度的常用 CF 写法 | K |
| `Q` | 气压层比湿 | kg/kg 或 g/kg | kg kg⁻¹ |
| `H` | 气压层高度或位势 | m、gpm，或 m² s⁻² | m |
| `SLP` | 海平面气压 | Pa 或 hPa | hPa |
| `PS_SOURCE` | 原再分析地面气压，可选 | Pa 或 hPa | hPa |

ERA5 的原始 `z` 是位势。将配置的 `H.variable` 指向 `z` 后，输入层根据单位识别并除以 **9.80665**；已经是高度的字段不再进行这一步。单位属性必须真实、可识别，不能只改变量名代替单位转换。`PS_SOURCE` 只用于比较，不直接替代与 LBM 地形一致的最终 PS；没有它时可以删除整段配置。

输入须满足以下条件：

- 气压层三维场使用一维 `pressure`、`latitude`、`longitude` 坐标；SLP、PS_SOURCE 使用相同类型的水平坐标。
- 纬度、经度单位须分别为 `degrees_north`、`degrees_east` 或程序识别的 CF 等价写法；弧度及西经/南纬为正的轴须先转换。
- 全球经纬网格为可表示成一维轴的规则网格或 Gaussian 网格，纬度覆盖目标 Gaussian 纬度，经度完整覆盖周期。程序不接受曲线网格、二维经纬坐标或区域截取资料。
- 气压坐标单位为 Pa 或 hPa；各气压层字段转换后的压力层必须一致。不同字段可以使用不同的水平网格，但同一字段的各月需要满足输入层的一致性检查。
- 时间使用可解码的 CF `time.units` 与日历。程序依据**实际时间坐标的年月**选择记录，不靠文件名猜月份；目标月份缺失或重复会报错。
- 可使用每月一个文件，也可使用一年或多年多记录文件；后者的模板不必包含月份。一个目标月应对应一条月平均记录，不能把小时资料直接当作月平均输入。
- 缺测值应通过 NetCDF 掩码、`_FillValue`、`missing_value` 或非有限值表示。程序会保留并统计缺测处理，不用全局均值填补缺失廓线。

不支持直接读取 hybrid/model-level 资料或 GRIB。需要先将这些输入准备为物理气压层 NetCDF。

### 三份模型参考文件

须自行从所使用的 **同一套 LBM T42L20** 环境提供：

| 配置键 | 通常的文件名 | 用途 |
| --- | --- | --- |
| `model.topography` | `grz.t42` | 模式的地形和地形一致的地面气压订正 |
| `model.sigma` | `GTAXLOC.CSIG20` | 精确的 20 层 σ 中心 |
| `model.template` | `erawin.t42l20` | Gtool3 背景文件记录、轴和格式模板 |

这些是数据/格式参考文件，无需模型可执行程序。真实参考文件及再分析数据不随代码分发；不要用其他网格或其他层数的文件替换。模板用于编码兼容，不表示新的再分析背景沿用模板中的气候场数值。

## 3. 配置与运行

从 [MERRA-2 DJF 示例](examples/merra2_djf.json) 复制一份配置，修改 `data_root`、三个 `model` 路径、输出目录及资料文件模板。示例中的 `/path/to/...` 均为占位符。

```bash
python -m lbm_background --config examples/merra2_djf.json --check
python -m lbm_background --config examples/merra2_djf.json
```

`--check` **只校验配置和三份模型参考文件**，不读取或验收再分析场，也不创建输出。它通过后，正式构建仍可能因资料缺月、重复记录、单位、网格、缺测廓线或最终质量检查失败而停止。正式命令读取输入并写入一套季节背景。

主要配置项：

| 配置项 | 说明 |
| --- | --- |
| `name` | 输出文件名前缀，使用安全的 ASCII 文件名字符；示例为 `merra2_djf_1991_2020` |
| `source_product` | 数据产品标识，写入来源元数据；填写真实产品 |
| `data_root` | 资料根目录，可用于文件模板中的 `{data_root}` |
| `output` | 必须为全新输出目录；相对路径以配置文件所在目录为基准 |
| `period.start_year`、`end_year` | 季节年份的闭区间 |
| `period.months` | 按季节先后顺序列出的连续月份，可跨年，例如 `[12,1,2]` |
| `period.minimum_valid_years` | 每个日历月、每个源格点的最少有效年份数；默认允许有部分缺测的月气候态，例子设为 1 |
| `coordinates` | 源坐标变量名：`time`、`latitude`、`longitude`、`pressure` |
| `fields` | 每个字段的 `files` 文件模板和 `variable` 源变量名 |
| `integrity.hash_inputs` | 是否计算输入文件 SHA256，默认 `true` |
| `integrity.require_receipts` | 是否强制要求已有 `.verified.json` 收据，默认 `false` |
| `diagnostics.plot` | 是否额外生成诊断图，默认 `false`，开启后需 `matplotlib` |

文件模板可使用 `{data_root}`、`{year}`、`{month}`、`{yyyymm}` 等受支持的占位字段；`{month:02d}` 可将整数月份格式化为两位。年度多记录文件示例：

```json
"U": {
  "files": "{data_root}/U/U_{year}.nc",
  "variable": "u"
}
```

示例采用 MERRA-2 的原文件命名：Q 目录下变量为 `QV`，GPH 目录下变量为 `H`，SP 目录下变量为 `PS`。若实际归档命名不同，应修改模板，不应为了匹配示例而改动科学变量。

### 季节年份与权重

跨年季节按**结束年份**标记。例如配置 DJF、1991–2020，需要 1990 年 12 月至 2019 年 12 月，以及 1991–2020 年的 1、2 月，共 90 个目标月份。MAM 的 `[3,4,5]` 则全部使用 1991–2020 年对应月份。一个配置生成一套季节；制作多个季节时复制配置，并分别指定全新输出目录。

平均顺序为：每个日历月先计算有效年份的格点气候平均，再将对应月气候场等权平均。季节平均要求所选各月均有效；**不是按每月天数加权，也不是对所有有效日或小时直接平均**。`minimum_valid_years` 控制月平均的采样下限；不同格点的有效年份可能不同，应阅读质量报告后决定是否提高到完整年份数。

### 输入完整性

普通 CF NetCDF 不需要先生成专用下载器收据。默认自行计算输入 SHA256；如文件旁已有 `文件名.verified.json`，程序会核对它的文件大小与哈希。设置 `require_receipts: true` 可要求每份输入都具有符合接口的收据。哈希证明所读文件的身份与完整性，不证明数据产品的物理正确性。

## 4. 保留的数值流程

1. 读取、核对各目标月份的 CF 时间、单位和坐标；按日历月对有效年份求气候平均。
2. 采用周期双线性插值，映射到精确的 128 × 64 Gaussian 网格；经度循环连接，缺测角点按有效权重重新归一。Gaussian 纬度为北到南，经度从 0° 开始。
3. 对指定月份等权平均。由 H–ln(p) 廓线和模型地形推算临时 PS，再得到近地面的 T/Q，以沿用原 `ecmsbs` 虚温递减率订正公式将 SLP 转换成与 LBM 地形一致的最终 PS。临时压力及最终压力按原流程作 T42 标量谱投影。
4. 使用模型参考文件的精确 σ 层，在 `ln(p)` 中作自然三次样条插值；每根廓线排除缺测层，超出有效压力范围时延伸最近有效端点的常值。H–ln(p) 推算压力的边界外处理使用最近两层延伸，与 P→σ 的常值端点规则不同。
5. 对 U、V、T、Q 的全部 σ 层分别作总波数不超过 42 的**标量球谐投影**。这里没有改为矢量球谐分析，也没有将 U/V 改成纬向平均。
6. Q 在谱投影后若出现负值，按原流程置零并记录。检查有限性、物理范围、谱重投影误差、端点延伸及相邻层位温差；温度不作人为稳定性修正。
7. 写出大端 float32 的 Gtool3 背景和逐层 Fortran 顺序 GrADS 数据，变量顺序为 **U、V、T、PS、Q**，PS 为 hPa。分别回读 Gtool3 与 NetCDF，逐值核对写出的 float32 数值，同时保存来源和质量报告。

源场单位归一与文件定位是本次可复用接口的一部分。水平、垂直和二进制算法沿用已核对的制作逻辑；原实验的固定日期、私人路径、任务状态和安装操作没有绑定到新的入口。

## 5. 输出及接入 LBM

默认输出包括：

| 文件 | 内容 |
| --- | --- |
| `<name>.t42l20` | 模式读取的 Gtool3 三维基本态 |
| `<name>.t42l20.grd`、`.ctl` | 配套 GrADS 数据和描述 |
| `background_sigma.nc` | 20 σ 层背景、压力、地形及诊断场 |
| `pressure_climatology_t42.nc` | σ 转换前的气压层气候场 |
| `quality_report.json` | 数值范围、谱检查、缺测、延伸和静力稳定度等 |
| `input_manifest.json` | 实际读取的输入、目标月份及完整性记录 |
| `output_manifest.json` | 构建产物的文件大小及 SHA256 |
| `build_status.json` | 构建状态或失败信息 |

开启绘图后还会生成背景态诊断图。模式文件使用约定的模式时间标签，实际气候时段在元数据和配置中单独记录；不要从模式时间 `0001-01-01` 推断气候平均年份。

将 LBM 实验配置中的 `BSFILE`、`cbs0` 指向同一套新生成的 Gtool3 文件，`cbs` 指向其配套 `.grd`。例如，按自己模式版本的语法设置：

```text
BSFILE = /path/to/output/merra2_djf_1991_2020.t42l20
cbs0   = /path/to/output/merra2_djf_1991_2020.t42l20
cbs    = /path/to/output/merra2_djf_1991_2020.t42l20.grd
```

上述是路径对应关系，不是可以直接粘贴到所有版本的完整 namelist。程序只制作文件，不替换现有实验设置，不安装背景到模式目录，也不启动积分。制作完成后，应自行进行模式读入、小步积分、稳定性及正式实验验收。

## 6. 软件验证与科学边界

可使用随包工具生成完全合成的再分析数据、模型模板和配置，先检查环境及完整的软件流程：

```bash
python tools/make_demo.py --directory /path/to/new_demo
python -m lbm_background --config /path/to/new_demo/config.json --check
python -m lbm_background --config /path/to/new_demo/config.json
```

指定的 demo 目录应是新的目录。**合成 demo 仅用于软件测试，不能作为科研背景态或模式正式试验输入。**

本次验证的范围包括离线数值/输入测试、合成数据与合成模板的完整构建，以及真实模型参考文件搭配合成再分析数据的完整构建。具体检查结果以随包验证报告为准。没有重新构建真实再分析气候背景，也没有进行 LBM 模型积分；原程序以前的生产资料验收、一天积分或正式实验结果不作为本包的验收结果。

运行随包离线测试：

```bash
python -B -m unittest discover -s tests -p 'test_*.py'
```

本次 42 项测试通过。真实模型参考文件搭配同一组合成再分析场时，新程序与服务器原 DJF 制作程序的 U、V、T、PS、Q 五个最终 float32 场逐值完全一致。该比较检验代码重构前后的计算一致性，不将合成资料转变为真实科学验收。

使用结果时须注意：

- 地形订正改变了 PS，最终 σ 层压力为 `σ × PS`，不能直接把原再分析 PS 当成最终 PS。
- 源压力覆盖不足时会常值延伸端点，尤其可能影响近地面或高层；延伸数量必须在报告中审查。每根廓线至少需要足够的有效层，资料缺失过重会停止构建。
- 标量 T42 投影保留原处理路线，不能等同于矢量风场的涡度/散度一致变换。
- Q 的非负截断可能重新引入高于 T42 的波数，因而 Q 不声明为截断后严格带限场。它也不能证明湿物理过程正确。
- 程序报告弱的相邻层负位温差，不自动调整温度；通过质量阈值也不等于已证明模式长期积分稳定。
- 不同产品的同名变量、月平均定义、湿度处理和高度定义仍需由使用者核对。更换产品、时段、缺测阈值或模型参考文件均应重新验收。

## 7. 代码与共享

```text
lbm_background/
  config.py      配置与季节月份
  inputs.py      文件、CF 时间、坐标、单位和完整性
  pipeline.py    气候场、地形订正、构建与诊断
  horizontal.py  Gaussian 网格、周期插值与标量 T42
  vertical.py    H→PS、SLP→PS、气压层→σ
  binary.py      Gtool3、GrADS 编解码
examples/merra2_djf.json
tools/make_demo.py
docs/SOURCE_PROVENANCE.md
```

示例和说明只使用占位路径，代码包不包含真实再分析资料、模型参考数据、SSH 连接配置或历史任务日志。运行生成的清单会记录实际输入路径；对外分享新生成的结果和日志前，应另行处理其中的私人目录。

原模型、资料和参考说明的使用条件仍由其提供方决定；本次作者署名描述此整理与重构工作，不替代第三方来源和许可。
