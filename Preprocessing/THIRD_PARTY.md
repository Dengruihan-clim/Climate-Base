# References, reuse and Climate-Base improvements

The 0.7.0 repository update for 2026-11-05 independently composes public xarray/Dask, xESMF and MetPy APIs while refactoring the author's original Climate-Base code. Validation was performed on 2026-11-01; development stages 0.4.0–0.6.0 were not separately published. No third-party numerical implementation is vendored in this package. References below identify design/API sources, not authorship of newly written code. The wider research record is [upstream-references.md](../docs/preprocessing/upstream-references.md).

cfgrib/ecCodes and Zarr/numcodecs have been optional extras since local 0.4.0. Local 0.5.0 added xESMF `regrid`; native ESMPy/ESMF is installed separately. Local 0.6.0 adds MetPy `vertical`; GeoCAT is not a runtime requirement because its corresponding public kernel is already MetPy. MetPy uses BSD-3-Clause, GeoCAT-comp Apache-2.0, and xESMF MIT; ESMF/ESMPy has its own license and bundled notices. Consult exact distributions. Version 0.7.0 adds metadata-only product adapters without a new runtime dependency. Meteostat remains planned; WRF adaptation is excluded. Core dependencies are NumPy, xarray, Dask, netCDF4 and cftime under their own licenses. No reference here changes any license.

Historical 0.6.0 validation includes four actual GeoCAT comparisons in addition to analytical truth and error-boundary cases. Windows source/wheel each recorded 593 passed and 26 skipped; core-only 483/136; the installed HPC candidate passed all 619 tests. The 35 runtime modules match byte-for-byte. Real ERA5 checks recorded 12 passes and 2 expected rejections with zero linear/log comparison error; hybrid fixtures use synthetic CF coefficients, not original model-level products. See [validation.json](validation.json) for exact scope.

Historical 0.5.0 numerical integration used xESMF 0.9.2 and ESMPy/ESMF 8.9.1 in Linux Python 3.12.16. That installed candidate passed 498 tests; real ERA5 P5 checks recorded 8 passes and 2 expected rejections. These historical counts do not replace current validation.

For every future algorithm/backend, document the official source/version, whether code was copied or independently implemented, any numerical changes, metadata/missing-value differences, and validation. If code is copied, retain its actual license/copyright and mark modifications; a source URL alone is insufficient.

The 0.7.0 product adapters independently implement explicit field/axis mappings,
scalar selections and metadata conflict checks using xarray. Their sources are
[ECMWF ERA5 documentation](https://confluence.ecmwf.int/plugins/viewsource/viewpagesrc.action?pageId=540945091),
[NASA MERRA-2 file specifications](https://gmao.gsfc.nasa.gov/media/publications/zbly36ziNFDFbmYmvhQeVqPhUo/Bosilovich785.pdf)
and [GDEX JRA-3Q d640002](https://gdex.ucar.edu/datasets/d640002/).
Exact profiles, opened field headers and limitations are recorded in
[the P7 evidence record](../docs/preprocessing/upstream-references.md#p7-具名产品证据).
No provider decoder, statistical algorithm or numerical implementation is copied.
Missing identity/statistical evidence remains a caller assertion; metadata
adaptation does not certify monthly sampling or every provider representation.
Synthetic MERRA-2/JRA-3Q fixtures validate contracts, separately from real ERA5
sample checks and current environment-specific results in `validation.json`.
MERRA-2 geopotential height additionally requires an existing matching
`standard_name`; no H-field interpretation or gravity conversion is inferred.
The multi-file integration preserves allowlisted raw range metadata per source
before adapter selection discards ranges that no longer describe its output.

The first 0.7.0 P7 stage is validated: Windows source and the tree-external installed candidate wheel each recorded **714 passed, 26 skipped**; core-only recorded **602 passed, 138 skipped**; the installed HPC candidate recorded **740 passed, no skips** (105 warnings). All 38 runtime modules and 77 Python files were byte-matched. Real ERA5 P7 checks recorded **10 passes and 4 expected rejections**, with zero original-value/API/CLI comparison error and unchanged source sizes/mtime. All three synthetic profile examples and their CLI runs passed. Original MERRA-2/JRA-3Q samples remain unvalidated. P8 station support is next; WRF is excluded, no runtime dependency was added, and these results remain dated 2026-11-01 for the 0.7.0 repository update.
