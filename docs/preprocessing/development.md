## 1. 学习管理方式，不复制整个工程

| 上游可学习的做法 | Climate-Base 的落地方式 |
| --- | --- |
| MetPy：源码、测试、文档、示例分离；一个 PR 处理一个逻辑变更 | Preprocessing 独立 `src/`；按实施计划拆变更；不把数据下载/生产任务写入库导入过程 |
| xarray：后端分层、依赖分组、数组类型兼容、安装与 CI 配置集中 | 保持 xarray 公共数据模型；可选后端延迟导入；先验证最小功能闭环 |
| cf-xarray：最小依赖、无可选依赖与常规环境分别测试 | CI 区分 core、最低支持组合、optional；缺额外依赖也能导入和用基础 I/O |
| GeoCAT：复用成熟内核；上游参考值与接口测试并行 | 不重写 ESMF/GRIB 解码/通用插值；保留解析场和兼容测试 |
| Meteostat：provider、目录、配置、缓存与公开 API 分工 | 联网获取和科学变换分离；记录来源；谨慎选择默认清洗/融合行为 |

不要求所有子项目改用同一打包工具。现有 setuptools 足够；不因 Meteostat 使用 Poetry 就强制迁移整个仓库，也不照搬成熟项目的大型 CI 矩阵。

## 2. API 与实现约定

- 公开接口少而稳定，新增时给类型标注与 NumPy 风格 docstring，写清单位、维度、日历、缺测、边界、是否触发计算、返回值及异常。
- 公共函数只做一类明确操作；纯数据变换不联网、不下载、不写磁盘、不修改输入对象。I/O 与 provider 的副作用显式暴露。
- 包装上游公开 API，不导入其下划线内部实现；保存兼容范围，在升级后运行本项目契约测试。
- 不用一个巨型 `utils.py` 放入所有逻辑；按元数据、时间、坐标、I/O、网格等职责组织。后端适配器不重复实现基础单位和日历规则。
- 参数不够确定时失败并指出缺少的信息，不用变量名或数据量级猜科学语义。警告应可定位到变量/坐标和动作，不包含凭据。
- 不把默认 `keep_attrs=True` 当作元数据正确性的证明；坐标关系、网格和单位改变后必须重验。
- 文件说明与科学约束分别处理：默认属性严格一致；显式 `preserve_sources` 只把指定的来源历史、处理日期和描述范围转存到逐输入审计。不得扩展为任意 `override`，也不得通过计算整场来隐式重算范围。
- `inspect` 的结构检查和 `validate` 的全量值扫描分别定义，日志说明是否读取数据和触发 Dask 计算。
- NetCDF/Zarr 共用时间写出契约：日期中心及 CF `bounds` / `climatology` 共享 `units`、`dtype` 与兼容历法，显式冲突报错。默认使用所需精度的 `int64` 编码；整微秒日期优先保留 cftime/旧接口可读取的微秒单位，实际亚微秒标签才使用纳秒。日期编码调整记入来源记录，不因数据变量名为 `time` 就跳过关联变量。
- 写出是明确执行边界：编码时可读取有上限的日期标签，完整临时产物发布前必须回读已识别的日期变量并逐值检查精度、缺失位置及历法语义。每变量至多 1,000,000 个标签，时间 bounds 端点和二维 `valid_time` 按总元素计数，超限拒绝发布；该检查不得额外全量读取气象数值场或任意 object 字段。

## 3. 测试与持续集成

已提供未启用的 [CI 工作流模板](preprocessing-ci.yml.example)，实际路径为 `docs/preprocessing/preprocessing-ci.yml.example`。需要自动执行时，将它复制到 `.github/workflows/preprocessing.yml` 后提交；启用后由 Preprocessing 或该工作流文件的变更触发。模板矩阵为 Linux/Windows、Python 3.11/3.12，另有一个保守依赖组合。本轮没有远端 CI 运行结果。按以下职责维护和扩展：

1. **静态检查**：CI 模板配置 Ruff，待启用后自动执行；当前已在本地执行。文档变更另检查 Markdown 相对链接与配置示例。格式检查按需补充，仅检查本次负责的代码范围。
2. **core**：Linux/Windows 的基础功能与旧接口回归；最低支持 Python 和一个经验证的新版本；小型合成数据、无网络。
3. **安装产物**：构建 wheel/sdist，在临时目标目录安装 wheel，在源码树外运行导入、CLI 和完整测试；避免 `sys.path` 掩盖缺包问题。`check_wheel.py` 复用所选解释器的已安装依赖，不宣称创建了完全独立的依赖环境。
4. **optional**：GRIB/Zarr、xESMF/ESMPy 与 0.6.0 MetPy 垂直插值均设真实后端用例。安装相应的 `.[dev,grib,zarr,regrid,vertical]` extras；ESMPy/ESMF 原生环境另行准备。GeoCAT 只作可选插值对照，未纳入运行 extra。同时验证仅核心依赖时仍能执行基础功能；缺后端跳过不算验收通过。WRF 不做适配，Dask 为核心依赖；Meteostat 任务留待 P8。
5. **文档与示例**：首个闭环后加入合成数据示例执行；联网样例显式标记，不作为默认 PR 测试前置。

新增测试以可观察契约为主：值、坐标、单位、元数据、缺测、错误边界、安装可用性及重要资源行为。文档改动只需适当文档检查；不为凑覆盖率编写镜像实现的测试。对缺后端的跳过给明确理由，不能把全部 skipped 报成该后端已通过。

日期写出用例必须覆盖中心/bounds/climatology 共享编码、显式编码冲突、纳秒标签与 NaT、远年 cftime 微秒、缺失位置和历法语义，以及回验不触发气象场读取。验收要求是“精确保留，或在发布前明确拒绝”；不能仅凭文件成功生成、`dtype=int64` 或较新 xarray 环境通过，宣称所有支持版本均能无损处理这些日期。旧后端发生时间舍入时须保留失败证据，并确认未发布最终 NetCDF 或带完成标记的 Zarr。

重网格验收分为无后端即可运行的几何/掩膜/指纹/缓存/CF 契约，以及真实 xESMF/ESMF 解析场、方法差异、周期接缝、NaN、静态掩膜与部分覆盖测试。面积积分采用匹配的 ESMF 大圆边界多边形几何，不能用普通点平均代替。允许读取声明的坐标/bounds 几何并构建权重，但字段图不应执行；`inspect` 即使带重网格配置也不得写缓存或结果。上游对照、解析真值及真实数据小样本分别记录，不能相互替代。

P6 将压力几何、输出元数据与 MetPy 数值内核分开验证。必须覆盖固定/两类混合公式、Pa/hPa、层中心与接口混淆、双向目标顺序、解析线性/对数场、原相邻缺口、精确层命中、地下层/缺 ps，以及延迟物理列检查。GeoCAT 作为同源内核的可选对照，不能替代独立解析真值。零场任务测试使用具名延迟字段，时间/bounds 解码的坐标任务另计，不把读取标签误称为读气象场。完整柱合块的内存代价和非垂直块保留均须说明；不声称通用加速比。流程应先完成单位转换与垂直插值，再做非有限值掩膜和水平重网格。

历史验证结果按版本保留，不用新结果冒充旧版本通过。当前 `validation.json` 记录 0.7.0 仓库版本在 2026-11-01 完成的源码、安装包和 HPC 验证；历史版本记录可由对应提交追溯，不把正在运行的验收记作成功。更新必须依据实际测试日志，记录时间、源码身份、精确依赖与命令。`SHA256SUMS.txt` 由 `tools/update_manifest.py` 生成；任何被清单覆盖文件发生变化时都应重新生成，不继续宣称旧摘要对应当前源码。包含账号、服务器路径和实际文件元数据的完整运行日志存放于公共仓库之外。

## 4. 依赖与环境

运行依赖、可选后端、测试、文档和开发工具在 `pyproject.toml` 分组。保留合理版本范围，CI 环境另保存可复现的解析结果；不把单台 Windows 工作站的完整环境导出当作所有平台的安装要求。

本机 Python 默认严格使用用户指定的 Anaconda 解释器。如需隔离环境，由该解释器创建并明确记录其派生解释器；不自行使用系统 Python。测试命令均通过选定解释器的 `-m` 运行，避免 `pytest/pip` 命令指向另一环境。

GRIB 环境分别记录 ecCodes Python 绑定与实际加载的原生库版本，不从 wheel 名称推断运行库。0.4.0 历史 Windows 配置为绑定/原生库 2.50.0/2.50.0，历史 Linux HPC 为 2.50.0/2.44.0；当时版本环境使用 `system-site-packages` 复用既有科学计算栈。该历史记录不代表当前独立环境的版本；后端身份以各阶段实际环境和测试记录为准。

xESMF 的 `regrid` extra 只声明 Python 依赖，ESMPy/ESMF 在独立受支持 Linux 环境中安装，遵循 [上游安装说明](https://xesmf.readthedocs.io/en/stable/installation.html)。0.5.0 历史验收环境为 Python 3.12.16、xESMF 0.9.2、ESMPy/ESMF 8.9.1。记录影响稀疏矩阵应用的其他依赖版本，全部参与缓存键。31 个运行源码模块已在本地、候选包与 HPC 间逐字节核对；该历史阶段的最终文档包经运行代码/测试/示例/工具逐字节核对后保留在本地，未重复部署 HPC。Windows 核心契约通过不替代原生后端测试。

依赖升级作为独立变更，检查上游发布说明和安装支持范围。xarray 当前主分支要求 Python ≥3.12，而本项目当前为 ≥3.11，实施时应验证兼容版本而非直接安装上游主分支。ESMPy 等系统和编译依赖单独说明；缺它们不影响基础导入。

## 5. 资料、缓存与来源

核心测试生成最小合成 NetCDF；可选测试用 ecCodes 自带模板生成具有自定义数值的真实 GRIB 格式，并在测试临时目录生成 Zarr v2。以后确需外部 GRIB 或其他支持产品夹具时，仅使用可公开分发的小样本，记录原始 URL、版本、许可、SHA256 和裁剪方式。由实际 NetCDF 值生成的 GRIB 只验证派生表示，不算原始 GRIB 产品验收。大数据使用单独缓存与清单，不入 Git，不携带用户凭据/本地路径。

从 Meteostat 学习请求缓存和源适配，但不要把自动清洗、多来源融合、模型补充变成隐式策略。原始响应缓存、规范化数据缓存、重网格权重缓存有不同键与失效规则，应分目录管理。缓存损坏需可检测；并发写入先临时文件后发布。

网络 provider 明确超时、有限重试、错误报告与离线模式。测试使用可追溯的小型固定响应或本地服务；仅另设人工触发或受控的 live 集成测试。

来源说明区分三类：直接调用外部依赖、参考设计后独立实现、引入/修改了上游代码。若真正复制代码，保留相应许可/版权及修改说明，并固定来源 commit。**首批实现由公开 API 独立组合并重构作者已有代码，没有复制第三方数值实现；模块内及 THIRD_PARTY.md 明确记录。**

仓库当前未见自身统一 LICENSE。上游许可证不自动授权本项目自有代码，也不等于气象数据许可；在正式发行前由维护者确定自有代码许可。无需因此阻塞本轮研究或本地架构工作。本轮不擅自新增许可证，也不变更已引入第三方代码的许可。

## 6. 变更、版本与发布

按 P1–P8 拆小变更；分支可使用 `codex/preprocessing-<topic>`。每次说明问题、最终行为、兼容影响与实际验证结果。重命名/文件移动、算法调整和依赖升级尽量分开，便于审查。

`CHANGELOG` 区分 Added/Changed/Fixed/Deprecated/Removed。破坏性变更不得藏在修复说明里；即使尚为 0.x，也应写出迁移方式。废弃接口先有可用替代与明确期限，再移除；本轮不废弃季节 API。

版本只维护一个来源；可采用 `_version.py` 的单一常量由打包配置读取，无需一开始引入复杂版本服务。发布前构建并验证安装产物、文档、来源/许可清单与依赖范围，再生成发布摘要。发布/push 与本地文档完成是不同状态，不将未上传文件描述为 GitHub 已更新。

## 7. 每个功能的交付清单

- 明确范围和输入/输出契约，附对应上游出处。
- 实现保持旧 API 兼容；新可选后端不会在基础导入时加载。
- 必要的科学边界和集成路径验证通过，未测路径如实记录。
- 中英文用户说明、示例、变更记录与来源说明同步。
- 验证包可安装，数据/缓存/私有路径未进入发布产物。

功能进入主线以实际通过这些验收为准，不以文件树齐全或占位函数存在为准。

## P7 产品契约验收

三类 profile 均需覆盖显式映射、已有声明冲突、缺证据来源记录、额外维精确标签选择、标量坐标保留、输入不变、CF 引用重写与零场任务。MERRA geopotential_height 须已有同名 source standard_name，缺该声明时即使单位匹配也拒绝。单值维不能绕过 selector；expver 不合并，未知角色不能依靠单位相同而放行。仅一条月标签不能证明整月采样完整，`cell_methods` 与时间 bounds 不得凭 profile 自动生成。

多文件按输入分别适配，再验证原严格合并策略；preserve_sources 必须保存选择前逐输入的白名单范围属性，不能因适配清理了过期范围而丢失原始审计；尤其测试源时间名映射、跨文件统计差异、同 shape 异网、资料与结果的关闭边界。MERRA-2/JRA-3Q 合成夹具只证明契约与流水线；真实 ERA5 检查单独记录来源表示和数值范围。官方 header 阅读、样本计算、完整全场是不同证据级别，不能互换。所有公开文档、日志摘要与验收记录继续去除私人账户及原始资料绝对路径。

0.7.0 首批 P7 验收完成：Windows 源码和树外实际安装的候选 wheel 各 **714 通过、26 跳过**；核心依赖环境 **602 通过、138 跳过**；HPC 安装候选包 **740 全通过、0 跳过**（105 条警告）。38 个运行模块及共 77 个 Python 文件逐字节一致。真实 ERA5 P7 为 **10 通过、4 项预期拒绝**，原值/API/CLI 对照最大误差 0，原文件大小和修改时间不变；三个 profile 的合成示例与各自 CLI 全通过。MERRA-2/JRA-3Q 原始样本未验收，不把合成契约检查当作真实数值通过。下一阶段为 P8 站点扩展；WRF 不做适配，未新增运行依赖，验证记录保留为 2026-11-01 的实际结果。
